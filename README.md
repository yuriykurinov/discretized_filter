# discretized_filter

Численная фильтрация марковского скачкообразного процесса со случайными
метками по дискретизованным наблюдениям.

Репозиторий содержит реализацию рекуррентного алгоритма фильтрации, генератор
траекторий сигнала и наблюдений, средства сохранения экспериментов и ноутбуки,
готовящие иллюстрации для статьи.

## Математическая постановка

### Сигнал

Ненаблюдаемый сигнал — пара `Z_t = (θ_t, Y_t)`:

- `θ_t` — однородный марковский процесс с непрерывным временем и конечным
  множеством состояний `{e_1, …, e_N}`, заданный матрицей интенсивностей
  переходов `Λ = (λ_ij)`. Диагональ определяется условием нулевой суммы строки:
  `λ_ii = −Σ_{j≠i} λ_ij`. Начальное распределение `p_0` по умолчанию берётся
  стационарным (левый собственный вектор `Λ` с нулевым собственным значением).
- `Y_t ∈ R^M` — кусочно-постоянная случайная метка. В момент каждого скачка
  процесса `θ` в состояние `e_n` значение `Y` разыгрывается заново, независимо
  от прошлого, из условной плотности `π_n(y)`. Между скачками `Y` постоянно.

Таким образом, траектория сигнала на отрезке полностью описывается тройкой
«число скачков — последовательность состояний — времена пребывания», а
`π_n(y)` задаёт распределение метки в каждом состоянии.

### Наблюдения

Наблюдения доступны только на равномерной сетке `{t_k}`, `k = 0…K`, с шагом `h`
(в коде — `ht`). За шаг сетки наблюдается приращение

```
Δξ_k = ∫_{t_{k−1}}^{t_k} f(θ_s, Y_s) ds + ∫_{t_{k−1}}^{t_k} g(θ_{s−}, Y_{s−}) dw_s
```

Наблюдение векторное: каждая координата — отдельный канал. В примере из
рабочего конфига каналов два:

| канал | тип | смысл |
|---|---|---|
| `ξ` | диффузионный | снос `f(θ, Y) = Y¹`, диффузия `g(θ, Y) = b·√Y¹` |
| `η` | считающий | пуассоновский поток с интенсивностью `h(θ, Y) = 1000·Y²/Y¹` |

Ключевое свойство схемы: **при фиксированной траектории сигнала на отрезке
параметры распределения приращения накапливаются линейно по временам
пребывания в состояниях**. Для диффузионного канала это даёт условную
гауссовость приращения:

```
Δξ_k | Z_[t_{k−1}, t_k]  ~  N( F(Z), G(Z) ),
F(Z) = Σ_i Δα_i · f(θ_{α_i}, Y_{α_i}),
G(Z) = Σ_i Δα_i · g g^T(θ_{α_i}, Y_{α_i}),
```

где `α_i` — моменты скачков `θ` внутри отрезка, `Δα_i` — времена пребывания,
`Σ_i Δα_i = h`. Для считающего канала так же линейно накапливается
интенсивность, а само распределение приращения — пуассоновское.

### Задача

Требуется вычислить условную плотность

```
ψ̂_k(y) = col( ψ̂¹_k(y), …, ψ̂^N_k(y) ),
P(θ_{t_k} = e_n, Y_{t_k} ∈ B | O_k) = ∫_B ψ̂^n_k(y) dy,
```

где `O_k = σ(Δξ_1, …, Δξ_k)` — σ-алгебра, порождённая наблюдениями.
По ней строятся оценки `θ̂_k = ∫ ψ̂_k(y) dy` (вектор апостериорных вероятностей
состояний) и `Ŷ_k = Σ_n ∫ y ψ̂^n_k(y) dy`.

## Алгоритм фильтрации

Основной результат (теорема в разделе «Вывод уравнений фильтрации») — рекуррентное
соотношение

```
ψ̃^m_{k+1}(y) = Σ_{r≥0} ∫ Φ^r(m, y, Δξ_{k+1} | n, v) ψ̂^n_k(v) ν^r(y, dv),
ψ̂^i_{k+1}(y) = ψ̃^i_{k+1}(y) / Σ_j ∫ ψ̃^j_{k+1}(v) dv,
```

где `Φ^r` — переходное ядро при условии ровно `r` скачков сигнала на отрезке,
а мера `ν^r(y, dv) = 1_{r=0}·δ_y(dv) + 1_{r≥1}·L(dv)` разделяет случай
«скачков не было» (тогда `Y` не изменилось, отсюда дельта-мера) и случай
«был хотя бы один скачок» (тогда `Y` переразыграно, интегрируем по мере Лебега).

### Обрыв ряда по числу скачков

Ряд по `r` суммируется приближённо — учитываются только первые слагаемые:

- `r = 0` — скачков на отрезке не было (`zero_jump_kernel`);
- `r = 1` — ровно один скачок (`single_jump_kernel`);
- `r = 2` — два скачка (`double_jump_kernel`), включается флагом `two_jumps`.

Точность аппроксимации оценена в разделе «Точность аналитической аппроксимации»:
при обрыве на `s` скачках погрешность в `L¹` мажорируется величиной порядка

```
2N · exp{h(λ_max − λ_min)} · (h·λ_max)^{s+1} / (s+1)!
```

то есть быстро убывает с уменьшением шага сетки `h`. Практический вывод: при
достаточно мелком шаге хватает одного скачка, и вклад `two_jumps` служит
проверкой этой оценки (сравнение приведено в `rmse_plots.ipynb`).

### Ядра

Явный вид слагаемых, реализованных в
[`src/discretized_filter/core/filter.py`](src/discretized_filter/core/filter.py):

**Без скачков** — состояние и метка не изменились, всё время `h` проведено
в `(m, y)`:

```
Φ⁰ = exp(h·λ_mm) · p( Δξ ;  h · c(m, y) )
```

**Один скачок** — время `τ` в старом состоянии `(n, v)`, время `h − τ` в новом
`(m, y)`, метка переразыграна из `π_m`:

```
Φ¹ = π_m(y) · λ_nm · ∫₀^h p( Δξ ;  τ·c(n,v) + (h−τ)·c(m,y) ) · exp(τ·λ_nn + (h−τ)·λ_mm) dτ
```

**Два скачка** — добавляется промежуточное состояние `(k, z)`, интегрирование
идёт по симплексу времён `τ₁ + τ₂ ≤ h`, и дополнительно суммируется по всем
промежуточным состояниям и узлам сетки.

Здесь `c(n, y)` — вектор *скоростей параметров* наблюдения, а `p(·; ·)` —
плотность приращения. Для гауссовского канала `c = (f, gg^T)` — ровно те
массивы, которые в коде исторически назывались `F` и `G`.

## Численная схема

| что дискретизуется | как |
|---|---|
| время | равномерная сетка с шагом `ht` на `[0, T]` |
| метка `Y ∈ R^M` | для каждого состояния `n` — своя прямоугольная сетка на `y_intervals[n]`, `num1` узлов по координате; декартово произведение даёт `M_net[n]` формы `(n_grid, M)` |
| интеграл по `y` | сумма по узлам с весом `delta[n]` — произведение шагов по координатам |
| интеграл по `τ` | формула прямоугольников с `n_points` узлами (по умолчанию — средних прямоугольников) |
| нормировка | после каждого шага `ψ` делится на `Σ_n Σ_y ψ[n, y]·delta[n]` |

Носитель `π_n` у разных состояний различен (`y_intervals` задаётся отдельно для
каждого состояния), поэтому и сетка, и вес `delta[n]` свои для каждого `n`.

Вся горячая часть скомпилирована `numba` (`@njit`, `fastmath=True`), внешний
цикл по узлам сетки распараллелен через `nb.prange` (`parallel=True`).
Стоимость одного шага фильтра — порядка `N² · n_grid² · n_points` операций для
однократного скачка, поэтому размер сетки `num1` и `n_points` определяют
время счёта в первую очередь.

### Назначение модулей

- **`core/filter.py`** — ядра `zero_jump_kernel`, `single_jump_kernel`,
  `double_jump_kernel`, шаг фильтра `filter_step` и класс `Filter`
  с методами `update(obs)` и `estimate()`.
- **`core/densities.py`** — плотности приращения наблюдений по каналам
  (нормальная, пуассоновская) и фабрика `make_obs_density`, собирающая из
  списка каналов совместную плотность. Пользователь может передать свою
  джитованную функцию с той же сигнатурой.
- **`core/smjp.py`** — `sparse_mc` разыгрывает траекторию `(θ, Y)` в разреженном
  представлении «состояние — метка — момент скачка»; `make_discretized_xi` и
  `make_discretized_eta` строят по ней приращения наблюдений на сетке.
- **`utils/distributions.py`** — семейства условных плотностей `π(y|θ)`.
  Каждое семейство хранит **и** плотность на сетке, **и** согласованный с ней
  джитованный генератор выборки, чтобы модель в фильтре и модель в генераторе
  траекторий не могли разойтись незаметно.
- **`utils/grids.py`** — `cartesian_product` (сетка по `Y`), `to_discrete`
  (перевод кусочно-постоянной траектории в значения на сетке фильтрации),
  `get_moments` (накопление среднего и дисперсии наблюдения по скачкам внутри
  шага сетки).
- **`utils/io.py`** — `save_path` / `load_saved_path` / `save_config_copy`.
- **`paths.py`** — определение корня проекта, чтобы пути к результатам не
  зависели от текущего каталога (важно при запуске из `notebooks/`).

## Конфигурация эксперимента

Каждый эксперимент описывается отдельным файлом `configs/config_<имя>.py`,
содержащим только «сырые» параметры. Производные величины (сетки, стационарное
начальное распределение, диагональ `Λ`, массивы плотностей) вычисляются
построителем при загрузке.

### Параметры конфига

| параметр | смысл |
|---|---|
| `exp_id` | идентификатор эксперимента; определяет каталог результатов |
| `T`, `ht` | правая граница интервала и шаг сетки фильтрации |
| `seed` | зерно всех генераторов |
| `N` | число состояний `θ` |
| `Lambda` | матрица интенсивностей без диагонали (диагональ заполняется автоматически) |
| `y_intervals` | носители `π_n` — по массиву формы `(N, 2)` на каждую координату `Y` |
| `num1` | число узлов сетки по координате |
| `pi_family` | имя семейства `π(y|θ)` или объект `PiFamily` |
| каналы наблюдения | список спецификаций: тип канала и джитованные функции сноса/диффузии/интенсивности |
| `n_points` | число узлов формулы прямоугольников по `τ` |
| `two_jumps` | учитывать ли слагаемое с двумя скачками |

### Загрузка конфига

```python
from discretized_filter.config import set_config
set_config('config_123')                    # активирует конфиг и сеет все ГПСЧ
from discretized_filter.config import *     # N, T, ht, M_net, delta, pi, ...
```

`set_config` находит файл в `configs/`, вычисляет производные величины,
инициализирует генераторы случайных чисел и публикует все имена в пространстве
модуля, после чего они доступны через `import *`. Активный конфиг — глобальный
на процесс; `get_config()` возвращает его, а при повторном вызове `set_config`
конфиг заменяется.

Для скриптов и кластерных задач имя конфига можно задать переменной окружения
`DFILTER_CONFIG` или аргументом `--config`.

## Запуск

```bash
# одна траектория: фильтрация и сохранение результата
.venv/bin/python scripts/run_single_path.py --config config_123

# оценка среднеквадратичной ошибки по ансамблю траекторий
.venv/bin/python scripts/run_monte_carlo.py --config config_123 --paths 10000
```

Типичный сценарий использования библиотеки напрямую:

```python
from discretized_filter.config import set_config
cfg = set_config('config_123')

from discretized_filter.core.smjp import sparse_mc
from discretized_filter.core.filter import Filter

# траектория сигнала и наблюдения по ней
theta, y, t = sparse_mc(cfg.p0, cfg.Lambda, cfg.lam, cfg.T, cfg.get_y, cfg.y_intervals)
observations = cfg.get_obs(cfg.t_net_filtering, theta, y, t)

filt = Filter(
    cfg.p0[:, None] * cfg.pi,      # начальная условная плотность
    cfg.pi, cfg.M_net, cfg.C,
    cfg.N, cfg.Lambda, cfg.ht, cfg.delta,
    cfg.obs_density,
    n_points=cfg.n_points,
    two_jumps=cfg.two_jumps,
)

theta_est, y_est = [], []
for obs in observations:
    filt.update(obs)
    th, yy = filt.estimate()
    theta_est.append(th)
    y_est.append(yy)
```

Первый запуск заметно дольше последующих: `numba` компилирует ядра.

## Формат сохранения результатов

Результаты одного эксперимента складываются в каталог
`saved_path_<exp_id>/` в корне проекта — по одному `pickle`-файлу на объект:

| файл | содержимое |
|---|---|
| `theta.pkl` | последовательность состояний `θ` в разреженном представлении |
| `y.pkl` | значения метки `Y` в моменты скачков |
| `t.pkl` | моменты скачков |
| `theta_est.pkl` | оценка `θ̂` на сетке фильтрации |
| `y_est.pkl` | оценка `Ŷ` на сетке фильтрации |
| `observations.pkl` | приращения наблюдений |
| `config.py` | копия конфига, с которым получен результат |

Результаты расчёта СКО по ансамблю сохраняются во вложенный каталог
`saved_path_<exp_id>/rmse_<N>_paths/` (`res_theta.pkl`, `res_y.pkl`).

Копия конфига сохраняется **автоматически** при запуске расчёта
(`save_config_copy`), поэтому по каталогу результата всегда восстановимы
параметры, которыми он получен.

Загрузка:

```python
from discretized_filter.utils.io import load_saved_path
theta, y, t, theta_est, y_est, observations = load_saved_path('example_for_arc_new')
```

Каталоги `saved_path_*` и `results/` не отслеживаются `git` (см. `.gitignore`).

## Соглашения разработки

- Пакеты — только через `uv`; системные `pip`/`conda` не используются,
  наличие `sudo` не предполагается.
- Комментарии и docstring — на русском в исследовательском коде и ноутбуках.

### Найденное при разборе кода

- В `zero_jump_kernel` множитель `exp(h·λ_mm)` применялся по одному разу на
  канал наблюдения, то есть фактически возводился в степень `K`. Множитель
  зависит от состояния `m`, поэтому искажал относительные веса состояний.
  При одном канале (`ia_example`) ошибка неактивна, при двух — активна.
  Исправляется в рамках текущей работы.
- Считающий канал `η` обрабатывается нормальной плотностью со средним, равным
  дисперсии, — это **диффузионная аппроксимация** пуассоновского приращения и
  предмет исследования, а не дефект (см. расчёты `results/diffusion_approx_*`).
  Конфиг `example_for_arc_new` сохраняет её в точности. Появившийся
  пуассоновский канал не заменяет её, а даёт точное правдоподобие, с которым
  аппроксимацию можно сравнить количественно: конфиг `example_poisson_eta`
  отличается от `example_for_arc_new` только видом плотности этого канала,
  порождающий процесс и траектория у них общие.
- Условная плотность зависимого распределения `Y` и разыгрывающий её генератор
  были написаны в разных файлах (плотность — в `config.py`, генератор — в ячейке
  `filtering.ipynb`) и не проверялись на согласованность. Реестр семейств
  `π(y|θ)` устраняет эту возможность расхождения.
